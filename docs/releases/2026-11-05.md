# November 5, 2026 stabilization release

This release combines #98 (#21 visual consistency) and #99 (#97 checklist-first
Cooking Mode), including the visually accepted November 3 compact planning/cooking
layout and Beerometer cleanup. It extends #96 (`925cbac`); #92/#84/#62/#85/#77/#86
are already delivered. Deployment status and exact integration/production SHAs are
recorded in the production release PR, after all gates pass.

## Behavior retained and completed

- Shared typography, vector icons, accessible controls and warm visual identity
  across planning, cooking, history and empty/error states.
- One current action, concise instruction, relevant estimate/checkpoint and checkbox.
  Physical-start recording/corrections and advanced logging stay in Step details.
- Latest append-only physical-start correction anchors forecasts. Original events,
  completion timestamps and saved history remain intact. Rapid check-offs never
  prove that a physical cooking/resting duration elapsed or food became ready.
- Accepted Beerometer design and math, with duplicate initial projected duration and
  zero elapsed hidden; useful distinct projected/remaining readings remain available.
- Compact mobile planning and cooking layout. Existing templates, scheduling,
  flexible reordering, account/guest behavior, persistence and recovery retained.
- No database migrations, auth configuration changes or production data mutations.

## Regression repair and validation

The reviewed #99 head `95a753d` failed only the desktop/mobile whole-cook-duration
assertions for the deliberately hidden initial projected/zero-elapsed lines. Both
failures were reproduced locally before changing assertions. The frozen-turkey
fixture intentionally includes five days of unfinished thawing in live execution;
its initial 155h30m remaining is not a new timing regression. Planning excludes the
advance thaw reminder from its cooking window, as before.

The updated regression checks numeric remaining duration, one-minute countdown,
nonzero elapsed, useful distinct projection and frozen archived actual duration.
It now also runs on iPhone/WebKit. Added focused coverage verifies append-only
backdated physical corrections, reload/reopen behavior and rejected future times.
Existing tests exercise multi-dish planning/edit/reorder/removal, rapid brisket
checks, pumpkin roast/cool estimates, delay/actual-start forecasts, resume, finish,
history/Cook Again, authentication, account isolation/retrieval and offline recovery.
Account browser tests use isolated fixtures, not production credentials or records.

Local typecheck, 277 unit tests and 32 focused desktop/mobile browser checks passed,
including a separate rerun of both actual-start correction checks after adding future-time
validation. Actual desktop/mobile captures were inspected before full GitHub Actions
unit/regression/auth/accounts/offline suites. Restricted workspace networking blocks
Playwright browser downloads; iPhone/WebKit executes in CI. A separate small
`cooking-review-screenshots` CI artifact supports inspection of actual desktop,
mobile and WebKit renders without downloading large trace/video reports.
Feature, merged-dev and exact production-candidate CI must all pass before promotion.
